## Build and deploy

If the two original checkouts are in use, edit the authoring checkout, inspect the differences, and copy only the changed source/media files to the hosting checkout. Include untracked files. Keep the hosting checkout's `wrangler.jsonc` and `HOSTING.md`. Do not mirror `.git`, credentials, build output, or dependency folders. A portable copy can use one source directory with the hosting files included.

Use Node.js 22.13 or newer compatible with the lockfile; the verified original environment is Node 22.22.2. Use the project's pinned tools rather than installing a different framework or updating dependencies as part of a content edit.

From the deployment directory:

```bash
npm ci --no-audit --no-fund  # first setup or after dependency changes
npm run build
npm run lint
git diff --check            # when this directory has Git metadata
```

Inspect visible content and layout for affected pages. Check project navigation after link changes and video playback after media/player changes. `npm run start -- --port 4188` can preview the production build locally; choose a free port and stop only the server started for this task.

For an authorized live update, verify `npx wrangler whoami` identifies the intended account. If authentication is missing, sign in on that computer with `npx wrangler login`; do not copy OAuth caches between computers. Use existing access and avoid adding permissions just to silence a CLI scope warning.

```bash
npx wrangler deploy --config dist/server/wrangler.json
```

`dist/server/wrangler.json` is generated by the build from `wrangler.jsonc` and Vite config. Never hand-edit it or deploy an old build. A dry run is available with the same command plus `--dry-run`.

Expected target:
- Existing Cloudflare account that owns the `moleworks.ch` zone.
- Worker: `moleworks-website`.
- Custom domains: `moleworks.ch` and `www.moleworks.ch`.
- `workers_dev` and `preview_urls` disabled.

The skill does not itself authorize publication. Follow the current request and existing session authorization; do not repeatedly ask for permission already given for the same bounded update. Do not create new projects, domains, accounts, or paid services to work around a deployment failure. Resolve build/authentication/target errors before retrying and verify the reported deployment version and live result. Record that version and meaningful checks in `HOSTING.md`.

Normal copy/design edits need affected-page checks, not a new DNS migration or mailbox test. For routing/hosting changes, check both HTTPS hostnames, homepage, `/research`, the three detail routes, and an unknown URL returning 404. Video playback worked, but byte-range requests previously returned full files with 200 rather than 206; recheck before claiming seeking support.
